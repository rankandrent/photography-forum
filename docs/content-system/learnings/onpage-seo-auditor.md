# Learnings: onpage-seo-auditor

Lessons this agent has learned. Read before every run; add new lessons at the end of every run.

## Owner rules (highest priority — written by the site owner, never removed by agents)

<!-- add owner rules here, e.g. "- Always prefer US cost/pricing keywords for the SaaS silo." -->
- 2026-10-06 (owner): Follow the Semrush on-page SEO checklist (docs/content-system/ONPAGE-CHECKLIST.md) on every page — blogs, services, industries, locations — and guide the writer and QA daily so every new post has the full checklist.
- 2026-10-12 (owner): on every page you audit, check the primary keyword in title, description, first meta keyword and OG tags, and the entity checks (`entity-coverage` ≥ 80%, `entity-salience` ≥ 75). Fix what is safe (add the keyword to a lead sentence or an H2, explain a missing entity with an existing fact from the site); send the rest to the writer as lessons. Never add an entity with an invented claim.
- 2026-10-12 (owner, layout-aware pages): audit `no-hidden-content`, `figure-caption`, `h2-then-text` and `table-intro` on every page and fix them (move an image below its answer, add a one-line table intro, add a caption). Never collapse main content again.
- 2026-10-12 (owner): service, industry and location section detail text is 50–70 words (90 max). Keep every named entity and attribute and the "no local office" line; cut filler. The owner found 100+ word sections too heavy once "Read more" was removed.

## Lessons (learned from runs, QA, audits and results)

<!-- lessons below -->
- 2026-10-06 (first run): markdown pages (about, privacy, terms) used `title` as both the H1 and the `<title>`, so short H1s produced 8–16-char titles. `content/pages/*.md` now accepts `metaTitle`. Rule: fix a short page title with `metaTitle` and leave the H1 alone.
- 2026-10-06: `has()` in onpage-audit.mjs needs every keyword word longer than 2 chars to appear literally, so a singular or a synonym fails ("Startup" vs "startups", "Fintech" vs "finance"). The "e-commerce" anchor also never matches the "ecommerce" slug. Rule: when writing a fix, use the anchor's exact word forms and keep any synonym as the angle after the `|`. Treat the ecommerce slug failure as a script issue and never change a URL for it.
- 2026-10-06: seo:check measures the description in built HTML, where an apostrophe renders as `&#x27;` (+5 chars). Rule: avoid apostrophes in descriptions within 5 chars of the 158/160 limit, or re-run seo:check after each one.
- 2026-10-07: the score cannot see readability. ux-audit-agency-vs-freelancer scored 100 while its first sentence used the keyword ungrammatically ("settle UX audit agency vs freelancer"). Rule: for every new post, read the title, description, first sentence and first H2 aloud before accepting a 100. "Keyword present" is the floor, not the bar.
- 2026-10-07: `has()` and the slug check now treat hyphen and space variants as one word through `norm()` and `compact()` ("e-commerce" = "ecommerce" = "e commerce"), which moved /industries/ecommerce/ from 96 to 100 with no URL change. Synonyms and singular/plural still fail on purpose. Rule: when a page fails only on a spelling variant, fix the matcher. When it fails on a synonym, fix the copy.
- 2026-10-07: some honesty facts are defined by their verb. While adding the /about/ link to saas-product-redesign, a first rewording turned "designed 200+ products" into "shipped 200+ products", which is a new claim. Rule: when you add a link to a sentence that holds a company fact (200+ products designed, since 2017, Reston HQ), link the existing words and keep every word of the fact unchanged.
- 2026-10-08: the alt check only tests that alt text exists, so template-made alt text can still be broken. `HomeSections.tsx` and `app/page.tsx` ran `role.toLowerCase()`, which turned "Principal UX Designer" into "principal ux designer" on / and /about/. Category titles were built as "Product design Guides". Every page still scored 100. Rule: once per run, grep the built `out/**/index.html` `alt="…"` and `<title>` values for lowercased acronyms (` ux`, `ui/ux`, ` kam`) and mixed case ("design Guides"). Fix the template line, not the content.
- 2026-10-08: each post brief (`content/briefs/<slug>.json`) has `backlinkSuggestions`, some marked conditional ("Apply only after SITE-FACT CONFLICT 1 is resolved"). Rule: before running `links:find` for a new post, read the brief's `backlinkSuggestions` and `notes`. Apply the ones not yet in place, and send the conditional ones to the owner as proposals, never as edits.
- 2026-10-08: "first run of an existing lesson" is not the same as "first time the gap happened". The 2026-10-06 writer lesson already asked for a description next step, yet 3 of 4 posts lack one. Rule: before calling a gap new, check every published post for it (`grep '^description:' content/blog/*.md`). If 2 or more pages already have it, escalate it now.
- 2026-10-09: "published in the last 2 days" includes location pages, which the location-publisher commits outside the blog pipeline and without a brief or QA report (b07e1e4, Philadelphia). Rule: start each run with `git log --since="2 days ago" --format="%h %s" -- content/` and the routes in latest.json that are missing from rotation.json. Review every new route, not only the post named in the task.
- 2026-10-09: template-made text can be wrong in grammar, not only in casing. The author bio picked "a"/"an" from the role's first letter, which gave "a SEO Manager" and "an UI/UX Designer", while both pages scored 100. Fixed in lib/blog.ts with an `indefinite()` helper that reads acronyms letter by letter. Rule: in the once-per-run sweep of built titles, alts and descriptions, also grep for `a [AEIOU]|an [B-DF-HJ-NP-TV-Z]` to catch template article errors, and fix the template.
- 2026-10-09: location pages share a headline pattern, "UX design agency <City> teams <verb>", which works as a headline (articles dropped). The same keyword breaks once it modifies another noun ("UX design agency Philadelphia project"). Rule: accept the keyword-first headline pattern in H1s and descriptions. Fix only the places where the keyword is stacked in front of another noun, and keep its section anchor if anything links to it (grep the old `#id` first).
- 2026-10-10: when the owner removes content, claims built from it can survive in hard-coded template metadata. After the fake logistics case studies were removed (10-09), `app/case-studies/page.tsx` still described the index as work "for SaaS, fintech and logistics teams". No logistics case study is left, and the page still scored 100. Rule: after any removal listed in RULES.md, grep `app/`, `lib/` and `content/home.ts` for the removed clients' industries and figures ("logistics", "supply chain", "warehouse"), and check each claim against the remaining `content/case-studies/*.md`.
- 2026-10-10: template alt text built from a fixed noun list is wrong for each image. The home industry tabs used "<Industry> UI UX design example: app and dashboard screens" for 6 different images. The healthcare image is phone screens only, SaaS is a pharmacy inventory dashboard, and startups is a studio website. Rule: when a commit adds images, open each one with Read and compare the alt with what is visible. Fix it with a per-item alt map in the template, never with a shared sentence. Also ask the owner about provenance when an image shows another designer's name or a mock brand ("Xiofik Hasan", "Zentara").
- 2026-10-10: a site-wide pattern defect is too big for the 10-edit budget. Five location pages share a broken FAQ question ("What tools does a UX design agency Boston teams hire from you use?"), and 14 location descriptions end on "From $5,000." with no next step. Rule: fix the pages under review first (new and in rotation), then put the remaining pages into one proposal with the exact old → new strings. Apply that proposal as a batch in the next run, before rotation, unless the owner objects.
- 2026-10-11: yesterday's batch proposal ("append 'Book a free consultation.' to the 13 descriptions ending 'From $5,000.'") could not be applied. The descriptions run 148–157 chars, and the 26-char suffix pushes every one past 158, while the task said "change nothing else". Rule: a batch proposal must list the exact new string and its length for every page, measured with `node -e` (and the built HTML for apostrophes), so the next run can apply it mechanically. Never propose "append X" without doing the arithmetic first.
- 2026-10-11: the "this choice" swap test misses article-parity defects. "Weighing a mobile app design agency vs freelancer" becomes "Weighing this choice", which passes, yet "a" covers only "agency" and leaves "freelancer" bare. The phrase came from the brief's own carrier list. Rule: for each `vs` hit, check for a head noun after the pair or an article on both halves, and trace a broken carrier back to `keywordCarrier` in the brief (a researcher lesson, not only a writer one).
- 2026-10-11: brief `backlinkSuggestions` marked "optional" are dropped by the pipeline. The home FAQ link to the mobile post was not in place at publish, while the required hub link was. Separately, hard-coded archive descriptions overclaim proof: /industries/ said "backed by real case studies" for 6 industries, but only finance and SaaS have tagged case studies. Rule: apply optional, non-conditional backlinks on publish day when they pass the relevance test. When you check archive metadata, compare each listed industry with `industries:` in content/case-studies/*.md.
- 2026-10-12: the score and the keyword-sentence checks never test whether a bold answer stands alone. In the new post, 2 "Why" H2s answered with "**Because…**" (a fragment as a snippet), and the post still scored 100 after 2 QA loops. Rule: in every new-post review, run `awk '/^## Why/{h=$0;getline;getline;if($0 ~ /^\*\*Because/)print h}'` on the file, and read each bold answer with its H2 hidden. A fix restates the subject in ≤ 30 words, counted word by word.
- 2026-10-12: the 10-edit budget and the carried city-description batch (7 edits) compete every run. On 10-11 the batch was blocked by arithmetic; today it was blocked by budget, because new pages (5 edits) and rotation (3) came first. Rule: next run, apply the batch first (7 edits, exact strings in the 10-11 report) unless the owner has objected, then use the remaining 3 edits on new pages. Review rotation pages but send their fixes to the report as exact old → new strings. If a batch is carried twice, it gets its own run.
- 2026-10-12: all 6 industry pages had descriptions that end on a benefit phrase ("experiences that sell", "users trust", "fewer errors on the floor") with no next step, and all 6 scored 100. Hard-coded archive and industry metadata repeat the gap the location pages had. Rule: once per run, list every `metaDescription` / `description` in content/ that does not contain "Book", "Request", "Send", "Get", "See" or "Compare", using `node` to print the length. Treat the result as the backlog for the next batch proposal.
