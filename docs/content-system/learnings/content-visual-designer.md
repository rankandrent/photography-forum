## Lessons (learned from runs, QA, audits and results)

<!-- lessons below -->

- 2026-10-05 (choose-ux-research-agency): Python-generated cover.svg had a shared line-style string plus an
  extra `stroke-width`, producing a duplicate attribute; Chromium's DOMParser rejected it ("Attribute
  stroke-width redefined") while the image still looked fine in a quick glance. Rule: never append an
  attribute to a reused attribute string; always run the DOMParser `parsererror` check on every SVG, not just a screenshot.
- 2026-10-05 (choose-ux-research-agency): Manrope is not installed in the render sandbox, so the fallback font
  is wider; a 470px pill label overflowed, and 18px bold questions over ~40 characters overran a 420px card.
  Rule: size text boxes for the fallback font (about 0.6em per character bold, 0.52em regular), wrap card
  text over ~36 characters onto two lines, and check getBBox overflow plus a screenshot before finishing.
  Playwright here is global (`/opt/node22/lib/node_modules/playwright`), not in the repo's node_modules.
- 2026-10-05 (choose-ux-research-agency): Process steps without a stated duration (e.g. "Observers invited")
  tempt invented timings on a Gantt. Rule: draw a bar only for durations the post states; show untimed steps
  as an icon and text row, and keep sublabels to words from the post (deleted an invented "Before sessions run").
- 2026-10-05 (choose-ux-research-agency, QA FAIL): all 5 inline infographics were drawn on a 1200px-wide viewBox with 14–18px text. The blog's `.prose img` shows them at 628px on desktop and 354px on mobile, so the text rendered at 7–9px on desktop and 4–5px on mobile, and could not be read. The screenshots had been checked only at native size. Rule: design for the rendered width. In a 1200px viewBox the smallest text is ≥ 24px and labels are ≥ 28px (≥ 12px at 628px), or use an 800px viewBox with ≥ 16px text. Keep graphics to labels and leave sentences to the post. Screenshot the image inside the built page at 1440px and 390px before handing back.
- 2026-10-05 (choose-ux-research-agency, repair round 1): the repair brief offered "800px wide with ≥ 18px text", but 18px in an 800px viewBox renders at 8px on the 354px phone column; the ≥ 11px-at-354px check needed ≥ 25px. Rule: derive the minimum font from the narrowest display width, `min_svg_px = 11 × viewBoxWidth / 354` (26px at 800 wide, 38px at 1200), and verify with `naturalWidth` vs rendered width inside the built page, not with a fixed px rule.
- 2026-10-05 (choose-ux-research-agency, repair round 1): the 800-wide redesigns worked by stacking one item per full-width card (red flags, proposal units, timeline steps each on its own row with a mini 10-day strip) and dropping every sublabel; tables became label + weight + blank boxes. Rule: for inline graphics, one idea per row, at most ~30 characters per line at 26px (wrap questions onto two lines), and let the canvas grow tall (800×1050 to 800×1570 was fine).
- 2026-10-05 (choose-ux-research-agency, repair round 1): the orchestrator had already swapped the markers into the post, so changing alt text in visuals.json does not reach the post on its own. Rule: when a redesign changes what an image shows, update visuals.json and also report the exact post lines whose alt text the orchestrator must replace.
- 2026-10-05 (choose-ux-research-agency, QA round 2 FAIL): the cover was drawn at 1600×600 with text from x=100. The post template crops it with `object-fit: cover` to 21:8 on desktop but 16:9 on mobile (`.pcover`, `app/globals.css`), so at 390px only x ≈ 267–1333 is visible, and the hero read "w to choose a / research agency". Rule: keep all cover text inside the 16:9 centre safe area, x 300–1300 and y 40–560. Make the smallest cover text ≥ 30px (≥ 10px at the 0.332 mobile scale). Screenshot `.pcover` in the built page at 390px.
- 2026-10-05 (choose-ux-research-agency, cover redraw after QA round 2): while I redrew the cover, the orchestrator also changed mobile `.pcover--img` to `aspect-ratio: auto` (the full 8:3 image, 354×133 at 390px), so the mobile scale became 0.221, not the 0.332 the brief assumed, and a 30px kicker rendered at about 6.6px. Rule: measure the live `.pcover` box in the built page before choosing sizes, design for both cases (all text in x 300–1300 for a 16:9 crop, and kicker/subtitle ≥ 36–40px for the uncropped 0.221 scale), and use a 3-line 80px title, which measured 300–961 with the fallback font. Also stop the server with `kill` on the PID, because `pkill -f "serve out"` matches and kills the calling shell.
- 2026-10-06 (saas-product-redesign): the first 628/354px screenshots showed 4 blank boxes. Images loaded with `page.setContent` (about:blank origin) cannot load `file://` SVGs, so the check silently proved nothing. Rule: write the harness HTML to the scratchpad and `page.goto("file://…/h.html")`, then confirm in the screenshot that the art actually rendered before reading any result.
- 2026-10-06 (saas-product-redesign): the cover text sat inside x 300–1300, but a wireframe drawn at x 80–270 still showed as a cut-off sliver at the left edge of the 16:9 mobile crop (visible x ≈ 267–1333). Rule: keep decorative line-art either fully inside x 300–1300 or fully outside it (x < 260 or x > 1340) so the crop never shows half a shape.
- 2026-10-06 (saas-product-redesign): a rollout marker placed right after a numbered 5-step list was drawn as an exposure-over-time step chart instead: y = share of accounts on the new UI, gate icons on each rise, dashed rollback arrows, an old-UI toggle bar and a sunset line, with no step names repeated. Rule: when a visual follows a step list, change the axis (time vs exposure, frequency vs change) so it shows a relationship the list cannot, and label example numbers on the image as "an example, not a norm" exactly as the post does.
- 2026-10-06 (saas-product-redesign, QA FAIL): rollout-exposure-curve.svg changed the axis to exposure over time, but every label on it (10/25/50/100%, "Gate: baseline metrics hold", "Old-UI toggle on", "Sunset", "flag steps back, no new deploy") was already in the numbered list or the sentence under it. QA failed it under the owner duplication rule. Rule: a new axis is not enough. List every label you plan to draw and strike any that appears in the adjacent list or table. If fewer than half the labels are new facts (for example a metric line against its target and rollback thresholds), skip the marker and tell the orchestrator.
- 2026-10-06 (saas-product-redesign, QA FAIL): in scope-decision-tree.svg, "confined to 1 journey? No" → "several stages leak? No" ended at "Not a redesign: price…". That routes a multi-journey, single-stage problem to pricing and contradicts the post, which tests "is the cause UX?" first. The footer also said "Durations and prices: see the table below" when the table has no prices. Rule: walk every root-to-leaf path of a decision tree as a real case and check each against the post's prose. Put the "is this a design problem at all?" exit first. Any text that points to the post ("see the table") must match what that table actually contains.
- 2026-10-06 (saas-product-redesign, repair round 1): the redrawn tree puts "Can users show the cause is UX?" first, so its "No" exit is the only route to "Not a redesign". Each later "No" now leads to a design scope, which means a multi-journey problem inside one stage reaches lifecycle or platform and never pricing. Making the 5-line "Not a redesign:" heading bold overflowed its 232px card (562–788 vs 540–772) under the fallback font. Rule: order a tree's questions as gate → smallest scope → largest scope. Before labelling nodes, re-read the alt text currently in visuals.json and the post (the writer may have reworded it after the fact-check) and copy those words exactly. Keep bold labels in narrow side cards to 12 characters or fewer at 26px, and re-run the getBBox card-overflow check after every weight change.
- 2026-10-06 (saas-product-redesign, QA round 2): after the repair, `rollout-exposure-curve.svg` was dropped from the post but still sat in `public/` and shipped to `out/`. The decision-tree `marker` in `.visuals.json` also still described the old, wrong logic. The "Not a redesign:" label ended 11px from its box edge, against 22px on the left. Rule: when a visual is removed, delete its file. When a visual is redrawn, rewrite its `marker` to match the new drawing. Keep at least 16px of right padding on the longest label in each box.
- 2026-10-07 (ux-audit-agency-vs-freelancer): mid-run, the orchestrator replaced the coverage-curve figures (about 35% / about 75% became NN/g's 20–50% / 74–87% ranges), and the writer and link builder rewrote the post's marker, takeaways and links while I was drawing. A marker copied from the first read would no longer have matched the post. Rule: build `visuals.json` with a script that pulls each `<!-- visual: … -->` from the post as it stands at write time and asserts `post.includes(marker)`. Then rerun a script that checks every table cell and list item in each `<details class="astext">` block appears word for word in the matching SVG's text.
- 2026-10-07 (ux-audit-agency-vs-freelancer): the first "Missing:" chip row wrapped by resetting x without moving down a row, and the card height was set before the chips were placed, so "evidence" was drawn on top of "effort". The getBBox check caught a text-vs-chip mismatch, and the screenshot confirmed it. Rule: lay chips and pills out into rows first (x, row), size the card from the row count, then draw. Check `font-size` on pill labels too: a 24px "Freelancer" pill broke the ≥ 26px rule at 800 wide, and a wider pill (196px) fixed it.
- 2026-10-07 (ux-audit-agency-vs-freelancer): the sourced figures were ranges, not points, so the chart draws them as solid pink bands (a bar at 1 evaluator, a box over 3–5) with the in-between shape as a dashed, soft-filled envelope and the footnote "Shading between the ranges is a sketch." The first label placement put two annotation boxes on top of each other, and the text-in-card check did not flag it because the overlap was box on box. Rule: plot sourced ranges as bands, and only as tick values. Place callouts beside the band, not under it, and check box-to-box overlap in the screenshot, because the getBBox card check misses it.
- 2026-10-07 (ux-audit-agency-vs-freelancer, QA loop 1): three SVG footers repeated a sentence the reader sees in the open prose next to the image: hybrid flow "Never hand AI output…", scope sheet "Without them, the cheaper quote…" and matrix "No prices: this compares…". The owner rule allows repetition only inside the collapsed "Show as text" block. Rule: do not draw a footer or takeaway line on an image. If a closing line is needed, check that it does not appear in the 10 prose lines around the image marker.
- 2026-10-07 (ux-audit-agency-vs-freelancer, QA loop 1): the "Missing:" chips on the sample-finding 4-up copied the writer's annotation, which was itself wrong (the in-house note lacked evidence and a fix too). Rule: when an image grades examples against a test stated in the post, recheck each chip row against that test yourself before you draw it, and flag any mismatch to the writer rather than copying it.
- 2026-10-07 (ux-audit-agency-vs-freelancer, repair loop 1): the matrix SVG had hand-typed cells, so the fact-check and QA rewrites to the post's table (6 cells) left it out of date. Rule: generate table infographics with a script that parses the post's markdown table at draw time. In this run 7 rows × 5 cells came straight from the post, and nothing needed retyping when the writer changed wording.
- 2026-10-07 (ux-audit-agency-vs-freelancer, repair loop 1): the word-for-word check matches each item against all of an SVG's text. A chip such as "evidence" therefore passes even when it is missing from the card it belongs to (it exists in another card). Rule: for graphics with repeated vocabulary (chips per card, cells per row), check each item inside its own card or group, or confirm card by card in the screenshot.
- 2026-10-08 (design-system-roi): the first break-even render had "Expected" over "Cumulative cost", "Month 23" over "Low", and the bold assumption labels ("Baseline UI hours", "Loaded hourly cost") running into their values. The getBBox text-inside-card check passed all of it, because each label still sat inside its card. Rule: also run a pairwise text-bbox overlap check on every SVG. On line charts, put line-end labels to the right of the plot, spaced at least 34px apart at 26px, and drop payback or event months to the x-axis on staggered rows. In label/value rows, put the label above the value.
- 2026-10-08 (design-system-roi): the writer had already put the final `![…](/blog/<slug>/<file>.svg …)` line under each `<!-- visual: … -->` marker, with file names and alt text. Rule: before naming files, read the line after each marker. If an image line is there, use its file name, take that exact line as the `markdown` in visuals.json (the script asserts they match), and warn the orchestrator that swapping the marker would show the image twice. Delete the marker instead.
- 2026-10-08 (design-system-roi): the worked-example chart was drawn from the post's assumptions with a monthly model in the generator. Before plotting, the generator asserts that the model reproduces every Results cell (Month 16 / Month 23 / Not within 60 months, −8% / 85% / 177%), and it places the payback dots at the model's crossing month. Rule: for any illustrative model chart, recompute the post's results from its stated assumptions in the generator and fail the build on a mismatch, then flag any mismatch to the writer. Never hand-place the curves.
- 2026-10-08 (design-system-roi, repair loop 1): a one-row text sync ("Loaded hourly cost" grew to a 3-line value). The generator's `block_after("<!-- visual: …")` failed with "substring not found" because the orchestrator had already swapped every marker for its image line. Re-anchoring on the image path `(/blog/<slug>/<file>.svg` worked. I backed up all SVGs, reran the generator and checked with `cmp` that only the target file changed (the other 5 were byte-identical). The model asserts and 88 word-for-word checks passed. Rule: anchor generators on the image path, not the marker, so repair loops can rerun them. Before handing back a repair, prove with a byte diff that no other file changed.
- 2026-10-09 (web-app-design-rfp): the getBBox check tests text only against the first rect of each `g.card`, so the 176px "Later phase" / "Out of scope" pills (text ~173px wide), a header pill that ran past x 760, and grid cells ending 6px from the card edge all passed the script. Only the screenshot showed them. Rule: wrap every pill or cell that holds text in its own `g.card` group (rect first) so the overflow check covers it. Size pills for DejaVu Sans (what `system-ui` resolves to here) at 0.64em per bold character, plus 40px padding, capped at the card width.
- 2026-10-09 (web-app-design-rfp): for the role × workflow grid, the word-for-word check matched one exact string per row card (workflow + scope + the 4 permission words in DOM order) against each card's joined text, and the rewrite card checked that each priceable card came right after its weak card. This proves that each "Edit/View/None" sits in the right row, which a per-item substring check cannot. Rule: when cells repeat a small vocabulary, check the whole row as one ordered string inside one card.
